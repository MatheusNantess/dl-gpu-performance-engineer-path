Primary lab device. Every benchmark in this repository references this record.

## Identity

Queried from `cudaGetDeviceProperties` on 2026-08-15, not from a datasheet.

- **GPU:** NVIDIA GeForce RTX 3060, 12 GB
- **Architecture / compute capability:** Ampere GA106, **8.6** → `nvcc -arch=sm_86`
- **VRAM:** 12.00 GB
- **Date recorded:** 2026-08-15

### Device properties

| Property | Value | Why it matters |
| --- | --- | --- |
| SMs | 28 | A grid with fewer than 28 blocks leaves SMs idle regardless of block size |
| Warp size | 32 | The scheduling quantum; every coalescing question is asked per warp |
| Max threads / block | 1024 | Upper bound on a single block |
| Max threads / SM | 1536 (48 warps) | 1024-thread blocks waste a third of the SM — only one fits |
| Registers / SM | 65536 | **65536 / 1536 = 42.6 registers per thread** at full occupancy |
| Registers / block | 65536 | |
| Shared memory / SM | 102400 B (100 KB) | |
| Shared memory / block | 49152 B (48 KB) default | Opt-in carveout raises this on sm_86 |
| L2 cache | 2359296 B (2.25 MB) | Small relative to the tensors this lab will move |
| Memory bus | 192 bits @ 7501 MHz | |

**Theoretical peak bandwidth: 360.0 GB/s** — computed as `2 × 7501 MHz × 192 bits / 8`. This is the datasheet ceiling, **not** an achievable figure, and must never be used as the denominator in a "percentage of peak" claim. The measured figure below replaces it.

## Notes

### Numerical baseline: CPU vs GPU fp32 disagree, and that is correct

Measured 2026-08-15 with a 512×512 fp32 matmul (`torch.manual_seed(0)`), TF32 off:

| Quantity | Value |
| --- | --- |
| Median \|result\| | 15.24 |
| Max absolute error | 4.77e-05 |
| Max relative error (where \|ref\| > 1) | 2.09e-05 |
| Elements failing `allclose(rtol=1e-4, atol=1e-5)` | 11 of 262144 (0.004%) |
| Median \|ref\| **at the failing elements** | 0.0244 |

The failures are concentrated entirely on near-zero outputs. `allclose` tests `|a-b| <= atol + rtol*|b|`; where `|b| ≈ 0` the `rtol` term vanishes and `atol` alone decides. Raising `atol` to 1e-4 passes.

The disagreement itself is not a bug and not TF32 — it is floating-point addition being non-associative, with the GPU accumulating in a different order than the CPU.

**Consequence for this lab:** a correctness test that reports pass/fail from a single tolerance is not enough. Report max absolute error, max relative error, and the magnitude of the reference at the worst element. A kernel that fails only where the reference is ~0.02 is a different situation from one that fails where the reference is ~15.

### Environment gotchas

- Privileged commands must run as `wsl -d Ubuntu -u root`; `sudo` blocks forever when there is no tty.
- Never install an NVIDIA driver inside WSL — it breaks the host passthrough.
- CUDA env lives in `/etc/profile.d/cuda.sh`, not `~/.bashrc`, because Ubuntu's `.bashrc` returns early for non-interactive shells.
- WSL is capped at ~7.7 GB RAM (50% of host). Raise via `C:\Users\mathe\.wslconfig` if it becomes a limit.
